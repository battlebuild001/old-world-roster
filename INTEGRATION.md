# Adding The Old World to BTH AoS Reference & Forge

The Old World builder now follows the AoS app's five-screen flow: factions, reference, forge, roster overview, and saved rosters. It remains a separate Site until a later merge is requested.

## Reusable pieces

- `dist/tow-core.js` is the game-specific domain adapter. It exposes `window.BTHTOWCore` with `GAME_ID`, `FORMAT`, roster normalization, faction-scoped storage, import/export, catalogue filtering, point totals, and supported validation.
- `dist/option-core.js` maps source option paths, composition availability, default selections, displayed upgrades, and point totals. Keep it alongside `tow-core.js` when merging.
- `dist/data/games/the-old-world/` contains the source army datasets. `dist/data/src/assets/the-old-world.json` provides the faction index. `dist/data/source.json` pins provenance; `DATA_ATTRIBUTION.md` records attribution.
- `dist/app.js` is the standalone presentation layer. It can be replaced by the AoS shell while retaining the core adapter and datasets.
- `dist/modern.css` and the reference screen present searchable unit cards, quick add, and visible rule keywords. The local rules index and `rule-aliases.json` map individual weapon names, including plural names in combined equipment lists, to book pages and `tow.whfb.app` URLs. Option and detail views show those links beside each choice. Rule text is fetched on demand from that external site and has a source-link fallback when unavailable.
- `dist/i18n.js` controls the Korean, English, and bilingual display modes. `dist/translations-ko.json` and `dist/translations-ui-en.json` are local display glossaries generated by the root build scripts. Keep source names, rule links, unit IDs, and option paths in English when merging; translate only the visible text. Live rule paragraphs are translated when opened, while the original English remains available in bilingual mode and through the source link.
- `dist/manifest.webmanifest`, `dist/pwa.js`, and `dist/sw.js` provide standalone installation and offline caching. A merged Site should register one service worker for the combined scope and add the Old World assets to its precache list.

## Compatibility contract

- Game ID: `the-old-world`.
- Export format: `{ "format": "BTH_TOW_V1", "game": "the-old-world", "faction": "...", "source": { ... }, "army": { ... } }`.
- Storage prefix: `bth_tow_`. The current faction and each faction's current army and saved list have separate keys. The earlier `old-world-bretonnia-roster-v1` record migrates on first load.
- Unit records keep `sourceId`, `sourceFaction`, `basePoints`, selected option paths, chosen magic items, and lore alongside total points. This preserves configured rosters across future data updates.

The AoS app's `BTH_AOS_V7` files and `bth_..._v7` storage keys remain independent. Route imports by `format` and `game`; do not treat Old World unit points as AoS warscroll points. The configurator prices the selectable unit options and magic items in the shipped data. Full army-composition validation, detachment handling, and conditional magic-item rules still need implementation.
